# 룬북 개인용 · 설계 명세서

작성 2026-10-09 · 초안 v0.1 (전문가 5인 회의 결과 통합, 독립 검증 전)
함께 보는 문서: `DATA_MODEL.md`(저장 구조·모순 점검 규칙), `PROMPTS.md`(AI 프롬프트·출력 검증)

## 0. 범위

사용자 1인이 쓰는 웹소설 집필 보조 프로그램이다. 상업 출시, 과금, 다중 사용자, 동기화, 출판 서식 내보내기는 범위 밖이다.
기존 룬북 기획서에서 이어받는 것은 다섯 가지다: 로컬 우선 저장, 설정 카드와 고유명사 자동 연결, 규칙 기반 모순 경고, AI의 질문·점검·선택지 중심 역할, 본문과 분리된 AI 패널.
기존 기획서의 "본문 대필 금지"는 개인용이라 한 단계 완화한다. 표현 추천에 한해 짧은 시연 문장을 허용한다(5절).

## 2. 시작 위저드

### 2.1 단계

단계 기호는 화면 기호(S1~S7)와 겹치지 않게 W0~W10으로 쓴다. 필수는 W0, W1, W2, W6이고 나머지는 "나중에"로 건너뛸 수 있다.

| 단계 | AI의 핵심 질문 | 저장 위치 |
|---|---|---|
| W0 장르·톤 | 주 장르와 보조 장르(비중)는? 독자에게 줄 쾌감은? 연재 목표는? | `project.genres`, `genre_weights`, `tone`, `target` |
| W1 한 줄 컨셉 | "___가 ___ 때문에 ___하는 이야기"를 채우면? 같은 장르 대비 비틀기 1개는? | `project.logline` |
| W2 세계 규칙 | 현실과 다른 점 한 가지는? 절대 안 깨지는 법칙 3개는? 일반인이 아는 것과 모르는 것은? | `world.premise`, `rules[]`, `secrecy` |
| W3 힘의 체계 | 힘의 원천은? 대가와 한계는? 등급 사다리와 주인공의 시작 위치는? (장르 템플릿 로드) | `systems/*` |
| W4 사회·세력 | 힘을 관리·독점하는 조직은? 주인공 편과 반대편 세력은? 돈과 자원은 어디서 나오나? | `factions/*` |
| W5 지리·시대 | 시대·연도는? 주 무대 3곳과 이동 소요는? 호칭·단위 등 어휘가 갈리는 지점은? | `world.era`, `places[]`, `mix_policy.vocab_zones` |
| W6 주인공 | 인물 질문 9단계(2.3) | `characters/*` |
| W7 조연·적대자 | 곁을 지킬 조력자는? 주인공의 믿음을 정면으로 부정하는 적대자는? 그가 옳다고 믿는 이유는? | `characters/*` |
| W8 관계 | 둘 사이의 비밀·빚은? 관계가 깨질 사건은? 서로 부르는 호칭은? | `relations.json` |
| W9 시작 사건·1화 훅 | 일상이 깨지는 순간은? 1화 마지막 문장의 훅은? 첫 선택과 그 대가는? | `timeline.json`, `scenes/sc_0001` |
| W10 확정 | 모순 점검 N건을 처리할까요? 미결 항목을 "나중에"로 남길까요? | `project.wizard` |

장르에 따라 W3~W5의 질문 은행이 달라진다. 혼합 장르는 질문의 합집합을 쓰되 문항 수를 제한한다.

### 2.2 한 턴의 흐름

한 번에 질문 하나를 묻고 후보 3개를 낸다. 후보의 `값`은 이미 저장 형식의 구조화 JSON이라서, 확정에는 AI 호출이 필요 없다.

| 상태 | 설명 |
|---|---|
| ASKING | AI 호출 중 |
| PROPOSED | 후보 3개 표시 |
| DRAFTING | 선택·수정·합치기 중인 초안 |
| CONFIRMED | 확정(리비전 +1 저장) |
| SKIPPED | 건너뜀(값 없음, "나중에" 큐에 보관) |
| AUTO | "AI가 알아서"로 채움 |
| PAUSED | 한도·로그인·오류로 일시정지 |
| DONE | 위저드 종료 |

| 작가의 동작 | 동작 결과 |
|---|---|
| 후보 선택 | PROPOSED → DRAFTING. 초안은 후보의 `값` |
| 고쳐쓰기 | DRAFTING 안에서 인라인 편집. 확정 시 AI가 수정 내용을 반영해 다음 질문을 만든다 |
| 합치기 | 체크한 후보 2~3개와 지시를 보내 새 후보 1개를 받는다. 원본은 흐리게 남는다 |
| 다시 제안 | 후보 3개를 교체. 거절한 후보의 제목과 한 줄 요약, 작가 힌트("더 어둡게")를 함께 보내 반복을 막는다 |
| 직접 말하기 | 한 줄 입력창. 후보를 만들 때 힌트로 쓰고, 직접 쓴 내용을 초안으로 삼을 수도 있다 |
| 건너뛰기 | 선택 단계만 가능. 값 없이 "나중에" 큐에 보관 |
| AI가 알아서 | 선택 단계만 가능. 추천 후보를 `ai_filled: true`로 저장하고 설정집에 "AI 임의 설정" 꼬리표 |
| 되돌리기 | 직전 리비전을 복원하고 캐시한 후보를 다시 보여 준다(재호출 없음). 뒤 문항이 이 항목을 참조하면 "이후 N개가 참조해요. 같이 되돌릴까요?"를 묻는다 |

앞 문항을 고치면 의존하는 뒤 문항에 "재검토 필요" 표시만 하고 자동 삭제하지 않는다.
AI는 질문 문장에 확정 항목 1~2개를 인용해 "앞에서 정한 X 때문에 이 질문을 합니다"라는 연결감을 준다.

진행률 = (확정 가중치 + 0.5 × 자동 가중치) / 활성 문항 전체 가중치다. 필수 문항 가중치 2, 선택 1이고 건너뜀은 분모에만 남는다.
장르가 확정되면 분모를 고정해 진행률이 뒤로 가지 않게 한다. "집필 시작 가능" 배지는 핵심 8문항(장르·톤, 세계 철칙, 힘의 체계, 주인공 3항목 등)이 차면 켠다.

### 2.3 인물 질문 순서

주인공과 조연은 같은 9단계를 쓴다. AI는 매 질문마다 후보 3개와 직접 입력란을 낸다.

1. 첫 장면에서 이 사람은 무엇을 하고 있나요?
2. 겉으로 원하는 것은 무엇인가요? (`desire.want`)
3. 가지지 못한 것, 잃은 것은 무엇인가요? (`lack`)
4. 그 때문에 믿게 된 잘못된 믿음은 무엇인가요? (`false_belief`)
5. 능력과 그 대가·약점은 무엇인가요? (`abilities`, `weaknesses`)
6. 말투: AI가 샘플 3문장을 내면 작가가 고른다. (`voice`)
7. 비밀은 무엇이고 누가 아나요? (`secrets`)
8. 시작, 전환점, 끝을 한 줄씩 적는다면? (`arc`)
9. 이미 만든 인물 중 누구와 얽히나요? (`relations`)

적대자는 5번 대신 "스스로 옳다고 믿는 이유"(`justification`)와 "주인공과 닮은 점"(`mirror_trait`)을 묻는다.

### 2.4 "AI가 알아서"의 범위 (기본값)

필수 4단계(W0, W1, W2, W6)는 작가가 후보를 고르거나 직접 입력해야 한다. 자동 채움은 허용하지 않는다.
선택 단계에서 자동으로 채운 항목은 "임시" 상태로 저장되고, 설정집에서 "AI 임의 설정" 필터로 일괄 검토한다.
이 기본값은 사용자가 바꿀 수 있다(11절 결정 1).

역사물의 기본값은 고증 수준 "느슨", 실존 인물 개입 수준 1(배경)이다.

### 3.2 혼합 정책 (`project.mix_policy`)

혼합 장르를 고르면 W3에서 아래 질문이 따라붙는다. 강제로 막지는 않고, 추천값을 한 번 수락하면 통과된다.

| 조합 | 반드시 정할 규칙 |
|---|---|
| 현대 무림 (헌터+무협) | 내공과 마력을 동일시(translate)할지 병존(parallel)할지와 환산식. 경지와 헌터 등급의 매핑표. 협회와 무림맹의 상하·경쟁 관계. 전투는 무협체, 사회는 현대체로 나누는 어휘 구역. 게이트 안에 무림이 있는지 |
| 사극 판타지 (역사+판타지) | 고증 수준. 마법이 있는 세계의 분기점. 실존 인물에게 마법을 허용할지. 신분제와 마법 재능의 충돌. 지명·연호를 실명으로 쓸지 |
| 빙의·회귀 | 지식 출처와 원작과의 차이 표. 바꿀 수 없는 사건과 바꿀 수 있는 사건. 나비효과 규칙. 회귀 횟수·트리거·한계. 사실을 아는 인물. 빙의 시 원주인의 능력 계승 여부 |
| 헌터+판타지 이세계 | 이동 방식(게이트=포털)과 편도/왕복. 두 마력 체계의 호환·변환. 시간 흐름비. 지구어와 이세계어 어휘 구역. 능력·아이템 보존 여부 |

공통 필드: `primary`, `system_relation`(replace/layer/parallel/translate), `vocab_zones[]`, `accuracy_level`, `rank_mapping[]`, `knowledge_holders[]`.
빙의·회귀 인물은 인물 단위로 현대어를 허용하는 어휘 예외를 둔다.

## 4. 집필 화면의 보조 기능

- **고유명사 연결:** 본문의 이름과 별칭이 설정 카드에 연결되고, 점선 밑줄이 표시된다. 탭하면 요약 팝오버(카드 제목, 요약 3줄, "설정집에서 열기"), 한 번 더 탭하면 카드 전체가 열린다. 한글 조합 중에는 조합이 끝난 뒤에 연결한다.
- **모순 경고:** 에디터 오른쪽 여백의 작은 점으로만 알린다. 소리와 팝업은 없다. 점에 올리면 한 줄 툴팁, 클릭하면 해당 카드가 패널에 얹힌다. 규칙은 `DATA_MODEL.md` 5절이다.
- **집중 모드:** 좌우 패널을 숨기고 본문만 남긴다. 경고 점과 "막혔어요" 버튼은 희미하게(투명도 0.5) 유지한다.
- **자동 저장과 버전:** 10분 단위 자동 버전, 전체 백업은 폴더 복사로 충분하다.

## 5. 맥락별 추천

### 5.1 호출

모든 호출은 사용자 클릭으로만 시작한다. 시점, 보내는 입력, 호출하는 템플릿은 `PROMPTS.md` 3절의 표를 따른다.
호출 버튼은 세 곳이다.

1. 에디터 우하단의 "막혔어요" 버튼. 누르면 "지금 어디쯤?"(맥락 탭), "다음에 뭘 쓰지?"(방향 탭), "이 문장 다르게"(표현 탭) 메뉴가 열린다.
2. 추천 패널 각 탭 상단의 "이 장면으로 새로 받기".
3. 문장을 선택했을 때 옆에 뜨는 "표현 추천" 칩(선택을 해제하면 사라진다).

장면 구분선을 넣거나 회차를 완료로 바꿀 때는 "추천 받기" 칩만 표시하고, 호출은 클릭 후에 한다.

### 5.2 추천 카드 3종

| 카드 | 핵심 필드 |
|---|---|
| 맥락 진단 | 이야기 위치 한 줄, 단계(도입/전개/위기/절정/여운)와 진행률, 긴장도 1~5와 직전 대비 변화, 열린 떡밥(최대 5개, 심은 회차·경과 회차·상태), 인물 상태, 독자가 기다리는 것(최대 3개), 위험 신호(늘어짐·설명 과다 등), 확신도가 낮을 때만 되묻기 |
| 방향 선택지 (3~4안) | 유형(안정/반전/파격), 제목 20자, 핵심 전개 2문장, 얻는 것, 위험, 연속성(OK/주의/충돌과 근거), 근거 카드·떡밥 1~3개, 연재 영향(고구마 +1, 훅 후보 등), 필요 장면 수. 채택해도 본문에는 아무것도 들어가지 않고 장면 메모의 "목적" 1줄에만 반영된다 |
| 표현 방법 | 시점, 템포(문장 길이, 대사:서술 비율, 모바일 줄바꿈 밀도), 감정 묘사 방식(직접/행동·신체/대조)과 쓰지 말 것, 인물별 말투와 금지어, 장르 관용 표현 3개, 피할 클리셰와 대체안, 시연 문장(대필 레벨 한도 안), 쓴 뒤 확인할 3항목 |

세 카드 모두 `복사` `장면 메모에 저장` `버리기` 버튼을 가진다. 본문에 직접 삽입하는 버튼은 만들지 않는다(11절 결정 3).

### 5.3 장르별 표현 가이드

표현 추천 프롬프트에 장르별 요약이 들어간다. 대표 항목은 다음과 같다.

| 장르 | 가이드 (일부) |
|---|---|
| 판타지 | 신규 고유명사는 한 장면에 2개 이하(가설). 능력 서술에는 대가와 제한을 함께. 작위·경칭 일관. 설정 설명 대사는 3문장 이내로 갈등 속에 분산 |
| 헌터물 | 상태창은 고정 박스 서식(`[이름: 강하준] [Lv.17] 근력 32 → 35`)으로 회차당 1~2회, 보상 순간에만(가설). `[알림]` 시스템 메시지는 한 줄에 하나씩 서술과 분리. 네 자리 이상 수치는 쉼표. 이전 수치를 반드시 참조 |
| 무협 | 호칭 세트(소협/대협/공자/낭자/사형/사제/사부, 자칭 소생/노부/본좌). 한자어 농도 3단계(낮음/중간/높음). 하오체·하게체. 초식명은 4자 한자어에 효과 1줄. 현대어(스킬, 레벨) 금지 |
| 역사물 | 신분별 말투(임금 "~사옵니다", 양반끼리 "~하오", 하인 "소인"·"나으리"). 시간은 "자시", "임진년 사월". 고증 수준 엄격/대체역사. 빙의·회귀물의 현대어는 내면 독백에만 허용. 금지 어휘 사전 |
| 혼합 | 어휘 구역 사전(현대 구역/무림 구역). 구역 간 번역어(마나=기). 시스템 메시지는 현대 구역, 대사는 인물 구역. 주/부 장르 비율로 관용어 가중치. 말투는 장면이 아니라 인물 단위로 고정 |

### 5.4 연재 특화 로직

- **훅:** 장면 끝과 회차 완료 때 마지막 300자의 훅 유형(질문/위기/반전/폭로/예고)을 분류한다. 같은 유형이 3회 연속이면 경고하고 방향 안에 훅 후보를 추가한다.
- **분량·템포:** 목표 분량 5,500자(플랫폼별 상이, 가설). 진행률 70%인데 절정이 시작되지 않았으면 "늘어짐"을 띄운다.
- **사이다/고구마:** 장면 라벨 3종(사이다/고구마/중립)을 최근 5회 윈도우로 집계한다. 고구마가 2회 연속이면 방향 안에 사이다 안을 1개 이상 포함한다. 초반 3화는 사이다 선행이다. 이 규칙은 설정에서 끌 수 있다.
- **떡밥 회수:** 회수 예정 회차를 지정하지 않으면 10회 경과 시 "방치"로 표시한다(가설). 회수 예정이 2회 이내면 "임박"이고, 방향 안 중 1개는 가장 오래된 떡밥과 연결한다.

### 5.5 대필 경계선

| 레벨 | 허용 | 비고 |
|---|---|---|
| L0 설계도 | 예시 문장 없음. 패턴 템플릿만(예: "[행동]+[신체 반응]+[짧은 대사]") | 가장 안전 |
| L1 시연 (기본값) | 항목당 2문장 80자 이내, 응답 전체 3개 이내. 복사·삽입 버튼 없음 | 표현은 설명보다 한두 문장 시연이 빨리 와닿는다 |
| L2 단락 시안 | 1단락(3~5문장, 300자 이내) 1개. 복사만 가능, 복사하면 회색 "AI 출처" 메모가 남는다 | 막힘 버튼에서 1회성으로 올림 |

모든 레벨에서 장면 전체 초안과 진행 중 장면의 이어쓰기는 금지한다. 시연은 "같은 기능의 문장"(감정 전달 방식, 말투)에 한정한다.
원 보고서의 L1 한도 120자와 80자 중 더 엄격한 80자를 택했다. 위저드에서 설정 항목을 제안하는 것은 대필이 아니다.

### 5.6 피드백과 반영

- 카드·안 단위 버튼: `쓸만함` `별로`(이유 칩) `숨기기` `메모 저장`.
- 이유 칩 6종: 설정과 안 맞음 / 너무 뻔함 / 너무 과격함 / 내 문체와 안 맞음 / 이미 생각한 것 / 장르 어긋남. 선택은 필수가 아니다.
- 암묵 신호: 채택과 메모 저장은 강한 긍정, 숨기기는 약한 부정.
- 반영 방식(모델 학습 없음): 같은 이유 칩이 3회 쌓이면 "선호 규칙 제안"을 띄운다(예: "파격 안은 설정 충돌 없는 것만"). 작가가 확정하면 `pref_rules`(최대 12줄)에 들어가 다음 호출에 한 줄씩 포함된다. 수정·삭제 가능. 숨긴 안의 제목 최근 5개는 중복 방지용으로 함께 보낸다. 안 유형별 채택률은 표시 순서에만 반영하고, 파격 안은 최소 1개 유지한다.

### 5.7 추천 품질 기준

1. 모든 방향 안의 근거 카드·떡밥 id가 실제로 존재한다(자동 검사 100%).
2. `연속성=OK`인 안은 규칙 엔진 검사에서 위반 0건이고, "충돌" 안은 충돌 근거를 가진다.
3. 한 호출의 3~4안은 결과가 서로 다르다. 작가 평가 "비슷함"이 10회 중 2회 이하다.
4. 시연 문장은 선택한 레벨의 한도 안이고 해당 장르 금지어가 0개다(자동 검사).
5. 고구마 2회 연속 뒤 호출에는 사이다 안이 1개 이상, 방치 떡밥이 있으면 회수 연결 안이 1개 이상 있다(자동 검사). 보조 지표로 20회 호출 중 채택·저장 4회 이상이면 통과로 본다(가설).

### 6.1 위저드는 턴 카드형

채팅형은 선택한 내용이 스크롤 속에 묻혀 무엇이 확정됐는지 안 보인다. 하나하나 쌓는 작업은 확정 지점이 눈에 보여야 한다.
후보 3개를 비교할 때도 말풍선 폭(약 560px)보다 카드 3열이 눈 이동이 적다. "같이 만든다"는 느낌은 카드 아래에 항상 열려 있는 "직접 말하기" 입력창과,
카드를 확정하면 AI가 한 줄로 받아 다음 질문으로 이어 가는 데서 나온다.

데스크톱 3열(대략 240px / 가변 / 360px): 왼쪽 단계 목록과 진행률, 가운데 현재 턴(최대 760px), 오른쪽 확정된 설정 카드가 쌓이는 패널.
새로 확정된 카드는 1.2초 강조된다(소리 없음). 빈 슬롯은 점선 "아직 안 정했어요".

### 6.2 집필 화면

열 폭 대략 260px / 가변 / 400px. 본문 열 폭은 34em이다. 추천 패널 상단에 AI 선택 세그먼트 `[자동 | Claude | ChatGPT]`가 있고, 모든 응답 카드에 `● Claude`
또는 `◆ ChatGPT` 배지와 소요 시간이 붙는다. 색만으로 구분하지 않고 도형과 글자를 같이 쓴다. `다른 AI에게도 물어보기`는 응답을 카드 스택 맨 위에 추가하고,
방향 탭에서는 데스크톱에 한해 `나란히 보기` 토글로 2열 비교한다.

상태: 첫 호출 전 빈 상태, 로딩(스켈레톤, "Claude가 읽는 중 · 최근 3장면 + 설정 카드 7장", 취소 버튼, 본문 편집은 막지 않음), 오류 3종(도우미 꺼짐 / 로그인 만료 / 사용 한도 도달).
오류도 패널 안에서만 표시하고 에디터를 가리지 않는다.

### 6.3 시각 스타일

- 순백/순흑을 쓰지 않는다. 라이트는 따뜻한 종이색, 다크는 어두운 갈회색이다.
- 본문 17px(폰 16px), 줄간격 1.85, 열 폭 34em(한 줄 32~38자). 본문 영역은 대비를 높게, UI는 한 단계 낮게 둔다.
- 상태는 색, 도형, 글자를 함께 쓴다. 모션은 150ms 이하이고 `prefers-reduced-motion`을 따른다. 소리는 없다.
- 본문 서체는 명조/고딕 토글을 둔다. Windows 기본 명조 계열은 바탕체뿐이라 의도한 질감이 안 나올 수 있다(11절 결정 4).
- 간격은 4px 배수. 터치 타깃은 폰 44px, 데스크톱 32px 이상.

색 토큰의 대비비는 WCAG 상대휘도로 계산한 값이다.

| 토큰 | 라이트 | 다크 | 비고 |
|---|---|---|---|
| `--bg` | #FAF7F0 | #1D1C1A | |
| `--panel` | #F2EEE4 | #262522 | |
| `--text` | #2A2620 (bg 14.05) | #E4DFD3 (bg 12.81) | |
| `--text-sub` | #6B6458 (5.47) | #A8A294 (6.70) | |
| `--accent` | #9A3412 (6.83) | #E8A66B (8.19) | 위 글자는 라이트 #FFFFFF, 다크 #1D1C1A |
| `--warn` | #B45309 (4.69) | #E0B04A (8.50) | |
| `--error` | #B42318 (6.14) | #F08A7E (7.01) | |
| `--ok` | #2F6B4F (5.88) | #7CC4A0 (8.32) | |
| `--line` | #DDD6C6 | #3A3833 | 장식 전용 |

장르 포인트 색은 칩과 프로젝트 카드 좌측 띠에만 쓴다: 판타지 #5B3F9E / #B9A2F0, 헌터 #0F6B78 / #6CC3CF, 무협 #8A2B2B / #E88F8F, 역사 #6F5410 / #D9B35C (라이트 / 다크, 모두 bg와 panel 위에서 4.5 이상).
AI 배지 색은 Claude #2F5A8C / #8FB5E8, ChatGPT #2F6B4F / #7CC4A0이다. 각 회사의 브랜드 색을 따르지 않은 중립 색이다.
`--text-faint`는 라이트 3.55라 텍스트에 쓰지 않고 아이콘·장식 전용이다.

### 6.4 반응형

| 폭 | 레이아웃 |
|---|---|
| 1200px 이상 | 3열(구조 / 본문 / 추천). 좌측 접기 가능 |
| 760~1199px | 2열. 구조 트리는 드로어, 추천 패널은 본문 옆 340px. 위저드의 확정 패널은 접이식 레일 |

## 7. 회의에서 갈린 지점과 결정

| 쟁점 | 의견 | 결정 |
|---|---|---|
| 위저드 단계 수 | 11단계 전부 필수 vs 최소만 필수 | 11단계를 안내하되 필수는 W0, W1, W2, W6 네 개. 나머지는 건너뛰기 가능 |
| 위저드의 구조화 출력 | 자유 서술 + 확인 단계 vs 후보를 JSON으로 | 후보는 짧은 JSON(`값`이 저장 형식과 1:1). 고쳐쓰기·직접 말하기는 자유 텍스트. 확정 전에 항상 카드 초안을 작가가 확인한다 |
| 추천 호출 단위 | 한 호출에 카드 3종 vs 카드별 호출 | 탭별 호출이 기본(필요한 탭만 한도 소모). 합본 호출은 선택 기능 |
| 세션 이어가기 | 무상태 재조립 vs 세션 이어가기 | 무상태 확정. 세션을 이으면 원고가 CLI 기록에 남고 시스템 프롬프트가 고정된다(8.2절). 압축·재시도·공급자 전환도 일관된다 |
| 호출 지연 vs 즉시 추천 | 맥락마다 즉시 vs 버튼 | 버튼 수동. CLI 최소 지연이 약 3.7초(실측)이고 직렬 큐라서 키 입력 단위 호출은 불가능하다 |
| 예시문 한도 | 120자 vs 80자 | 항목당 80자 |
| 'AI가 알아서' 자동 확정 | 즉시 확정 vs 임시 | 임시 상태 + "AI 임의 설정" 꼬리표. 필수 4단계에는 쓸 수 없음 |
| 모순 경고 위치 | 문장 단위 점 vs 장면 단위 배지 | 장면 단위가 기본. 이름·수치가 본문과 정확히 일치할 때만 문장 단위 |
| 본문 삽입 버튼 | 복사만 vs 미리보기 후 삽입 | 복사·장면 메모만. 삽입 버튼은 만들지 않음 |

## 8. AI 구독 연결

### 8.1 구조

| 계층 | 역할 | 선택 |
|---|---|---|
| 프론트 | 위저드·에디터·AI 패널 | 정적 HTML + 바닐라 JS, 빌드 없음. 시안 코드가 그대로 출발점 |
| 로컬 도우미 | 정적 파일 서빙, 저장 API, AI 어댑터, 호출 큐 | Node 22 단일 `server.mjs`, 의존성 0 |
| 저장소 | 원고·설정집·이력 | 사용자 폴더의 JSON/Markdown 파일 (`DATA_MODEL.md`) |

실행은 `룬북.bat` 더블클릭이다(`chcp 65001` → `node server.mjs` → 브라우저로 `http://127.0.0.1:포트/#t=토큰` 열기). Node 설치 여부는 사용자 PC에서 확인해야 한다.
데이터 폴더는 코드 폴더와 분리한다(예: `D:\바이브 코딩\룬북데이터`). OneDrive 같은 동기화 폴더는 원자적 교체와 충돌할 수 있어 피한다(가설).
폰은 v1에서 지원하지 않는다. 필요하면 2단계로 같은 Wi-Fi 한정이고, 이때는 `--lan` 옵션을 켠 때만 바인딩을 넓히고 기기별 페어링 토큰을 쓴다. 포트포워딩과 터널 공개는 하지 않는다.
AI 호출은 항상 PC에서 실행되므로 PC가 켜져 있어야 한다.

### 8.2 어댑터 인터페이스

```ts
interface AiAdapter {
  id: 'claude'|'codex'|'mock';
  status(): Promise<{installed:boolean; version?:string; loggedIn:boolean; authMethod?:string; warnings:string[]}>;
  complete(task:{kind:string; ref?:string},
           prompt:{system:string; user:string; schema?:object},
           opts:{model?:string; timeoutMs?:number; signal?:AbortSignal; onDelta?:(t:string)=>void}
  ): Promise<{ok:true; text:string; json?:any; usage?:object; limit?:{status:string; resetsAt?:number}; durationMs:number; model?:string}
           | {ok:false; error:{code:'NOT_INSTALLED'|'NOT_LOGGED_IN'|'LIMIT'|'TIMEOUT'|'CRASH'|'PARSE'|'ABORT'; message:string}}>;
}
```

**무상태가 기본이다.** 맥락은 앱이 매번 조립해서 넣는다. 세션을 이으면 원고가 CLI 쪽 기록(`~/.claude`)에 남고, `--resume`에서는 시스템 프롬프트가 첫 요청 시점 것으로 고정된다.
아키텍트가 `--no-session-persistence` 없이 실행했을 때 임시 작업 폴더마다 `~/.claude/projects/` 아래에 기록 폴더가 생기는 것을 확인했다. 그래서 이 플래그를 항상 붙인다.

프론트는 `AiClient`(`complete(req) → AsyncIterable<AiEvent>`)만 알고 `fetch`는 한 파일에 모은다. 시안에서는 같은 인터페이스를 브라우저 안의 모의 객체가 구현한다.

### 8.3 Claude (`claude -p`)

표기 `[실측]`은 아키텍트가 이 컨테이너(Linux, Claude Code 2.1.295, 구독 OAuth 로그인)에서 직접 실행해 확인한 것이다. Windows 실행은 검증하지 않았다.

| 항목 | 내용 |
|---|---|
| 비대화 실행 | `claude -p`. 프롬프트는 stdin으로 넘긴다(상한 10MB) |
| 출력 | `--output-format json`(필드 `result`, `session_id`, `is_error`, `subtype`, `total_cost_usd`), 스트리밍은 `--output-format stream-json --verbose --include-partial-messages`의 `text_delta` [실측] |
| 구조화 출력 | `--json-schema`로 `structured_output` 필드 |
| 도구 차단 | `--tools ""`(init에서 `tools: []` 확인 [실측]), `--strict-mcp-config`, `--disable-slash-commands`, `--safe-mode`(CLAUDE.md·훅·플러그인·MCP 비활성, 인증은 정상 [실측]) |
| 디렉터리 격리 | 빈 임시 폴더를 작업 디렉터리로 지정. 네이티브 Windows는 샌드박스를 지원하지 않으므로 도구 차단이 유일한 방어선이다 |
| 시스템 프롬프트 | `--system-prompt-file <파일>`(기본 프롬프트 전체 교체) |
| 모델 | `--model sonnet\|opus\|haiku\|전체 ID`. 목록은 설정 파일로 분리 [실측: sonnet이 claude-sonnet-5-5로 해석] |
| 로그인 확인 | `claude auth status`(JSON, 로그인 시 exit 0, 아니면 1) [실측] |
| 구독 사용 | 구독 OAuth 로그인으로 `-p`가 동작한다 [실측: `apiKeySource: none`] |
| 한도 | 5시간 세션 + 주간 한도이고, Claude 채팅과 Claude Code가 한 풀을 공유한다. `-p`에서 한도 초과 시 동작은 문서에 없다. 스트림에 `rate_limit_event`(`status`, `utilization`, `resetsAt`)가 나왔으나 공식 문서에는 없다 [실측] |
| 지연 | 최소 호출 약 3.7초 [실측, Linux]. 키 입력마다 호출하는 설계는 불가능하다 |

고정 호출 형태(argv는 상수이고 사용자 텍스트는 전부 stdin) [실측 통과]:

```
claude -p --output-format stream-json --verbose --include-partial-messages
       --tools "" --safe-mode --strict-mcp-config --disable-slash-commands
       --no-session-persistence --system-prompt-file <파일> --model <별칭>
```

**함정 3가지**
1. `--bare`는 OAuth를 읽지 않아 구독에서 쓸 수 없다.
2. `-p`는 환경변수 `ANTHROPIC_API_KEY`가 있으면 구독보다 우선해 API 요금이 부과된다. 도우미는 자식 프로세스 환경에서 이 변수를 제거한다.
3. 빈 문자열 인자(`--tools ""`)가 Windows `spawn`에서 그대로 전달되는지는 미검증이다. 대안으로 `--disallowedTools "*"`(문서상 모든 도구 제거)를 준비한다.

실패 시 인증 오류 등은 stdout에 결과로 나오고 exit는 0이 아니다. 그래서 exit code와 JSON의 `is_error`/`subtype`을 모두 본다.

### 8.4 ChatGPT (Codex CLI) — 컨테이너에 Codex가 없어 실행 검증하지 못했다

아래는 openai/codex 저장소 소스와 문서 검색 요약에 근거한 것이다. developers.openai.com은 이 환경에서 차단되어 원문을 읽지 못했다.

| 항목 | 내용 |
|---|---|
| 비대화 실행 | `codex exec`. 프롬프트 인자를 생략하거나 `-`이면 stdin |
| 출력 | `--json`은 JSONL 이벤트(`thread.started`, `turn.started`, `turn.completed{usage}`, `turn.failed`, `item.*`, `error`). 답은 `agent_message{text}` 항목 |
| 스트리밍 | 스키마에 토큰 단위 델타가 없다. 문단 단위로 도착할 가능성이 높다(가설) |
| 구조화 | `--output-schema FILE`, `-o FILE` |
| 샌드박스 | `-s read-only` 등. 도구를 완전히 끄는 플래그는 찾지 못했다(미확인). read-only여도 읽기는 가능할 수 있다(가설) |

| 구독 사용 | ChatGPT 로그인이 구독 경로다. API 키로 로그인하거나 `CODEX_API_KEY`가 있으면 구독 대신 API 요금이 적용된다 |

고정 호출 형태 [미실측]: `codex exec --json --ephemeral --skip-git-repo-check -s read-only -C <빈 폴더> --color never -m <모델> -`
Codex는 도구 완전 차단 수단이 미확인이라 Claude보다 보안이 약하다. 구현 첫 단계에 Windows에서 `codex exec --json` 샘플을 캡처하는 시험을 넣는다.

### 8.5 호출 실행기(runner)의 안전장치

- argv에는 고정 플래그만 둔다. 사용자 텍스트는 전부 stdin으로 넘긴다. Windows 명령줄 길이 제한과 인용 문제, `-`로 시작하는 텍스트가 플래그로 오인되는 문제를 피한다.
- `shell:false`, `windowsHide:true`, 실행 파일은 전체 경로로 지정한다. `.cmd` 셔틀은 셸 없이 못 띄운다.
- 환경변수는 허용 목록만 전달하고 `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `OPENAI_API_KEY`, `CODEX_API_KEY`, `CLAUDE_CODE_USE_*`는 제거한다.
- 동시 실행은 전체 1개, 대기열 최대 5개, 대기 중 취소 가능.
- 타임아웃: 첫 바이트 60초, 무출력 90초, 전체 300초. 초과 시 프로세스 트리를 종료한다(Windows는 `taskkill /T /F /PID`로 가정, 가설).
- 스트리밍: 자식 stdout을 줄 단위로 파싱(멀티바이트 경계는 `StringDecoder`로 보호)해 SSE로 프론트에 중계한다. 클라이언트가 끊으면 자식도 종료한다.
- 비정상: exit≠0, JSON 파싱 실패, `is_error:true`는 오류 코드로 매핑한다. stderr는 64KB로 제한하고 내용은 저장하지 않는다. 구조화 응답은 스키마 검증 후 1회만 재시도한다.
- 인코딩: 파이프는 바이트이므로 UTF-8로 직접 디코딩한다. `.bat`에 `chcp 65001`, 파일은 BOM 없는 UTF-8.
- 시간당 호출 수 소프트 상한을 두고, 넘으면 확인 창을 띄운다. 자동 반복·배치·야간 예약 호출은 만들지 않는다.

### 8.7 보안

- 바인딩은 `127.0.0.1` 고정(`localhost`는 쓰지 않는다). 시작 시 무작위 토큰 32바이트를 만들어 URL 해시(`#t=`)로 전달한다. 해시는 서버로 전송되지 않는다. 프론트는 `sessionStorage`에 보관해 모든 `/api` 요청에 `Authorization: Bearer`로 보낸다.
- Host 헤더가 `127.0.0.1:포트`/`localhost:포트`가 아니면 거부한다. Origin이 있으면 자기 오리진과 일치해야 한다(DNS 리바인딩 방어). CORS 헤더는 내지 않고 JSON `Content-Type`만 허용한다.
- 정적 파일은 허용 폴더 안에서만 서빙한다. 저장 API는 경로가 아니라 ID로만 접근한다. CSP는 `default-src 'self'`.
- 로그: 원고·프롬프트·AI 응답은 서버 로그에 남기지 않고 메타데이터(시각, 작업 종류, 공급자, 소요, 바이트, exit, 오류코드)만 남긴다.
- 프롬프트 인젝션: Claude는 도구가 없어 피해가 출력 조작으로 한정된다. 응답은 `textContent`나 HTML을 제거한 Markdown으로만 렌더링하고 본문에 자동 삽입하지 않는다. Codex는 읽기 권한이 남을 수 있어 빈 작업 폴더와 read-only가 필수다.
- AI 대화 기록은 작품 폴더(`ai/`)에 사용자 데이터로 저장한다. 서버 로그와 구분한다.

### 8.8 저장 동작

- 원자적 저장: 같은 폴더에 `.tmp`로 쓰고 `fsync` 후 `rename`. Windows에서 백신·색인기가 파일을 잡고 있으면 EPERM/EBUSY가 나므로 짧은 백오프로 5회 재시도한다(실측 필요). 직전본은 `.bak` 1개 유지.
- 동시 편집: 문서마다 `rev` 정수를 두고 불일치하면 409. 중복 실행 방지용 `.lock`(pid).
- 10분 자동 버전: 변경 해시가 달라졌을 때만 스냅샷. 24시간 전부, 7일은 시간당, 30일은 일당으로 솎아낸다. 수동 저장점은 영구 보존. 백업은 종료 시와 일 1회 폴더 복사.
- 마이그레이션: 모든 JSON에 `schemaVersion`. `migrations/vN_to_vN+1.mjs`를 순차 적용하고 적용 전에 전체를 복사한다. 더 높은 버전의 파일은 열지 않고, 알 수 없는 필드는 보존한다.

### 8.9 HTTP API 경계 (`/api/v1`, 토큰 필요)

| 메서드·경로 | 용도 |
|---|---|
| GET `/health` | 버전, 스키마 버전, 데이터 폴더 |

AI 호출은 작업 단위 비동기 잡(POST + SSE)이다. 큐 대기와 재접속을 같은 방식으로 다룬다.
