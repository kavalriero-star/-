## 0. 개념 전환 (2026-11-01)

사용자 요청으로 기본 개념이 바뀌었다. 상세는 `CONCEPT_V3.md`.

- **AI와 함께 쓴다.** 본문 대필 금지 원칙을 폐기하고, Claude가 장면 초안·이어 쓰기·다듬기를 한다. 작가는 방향을 정하고 받아들일지 결정한다.
- **그림은 ChatGPT.** 장면 일러스트, 세계 지도, 도시·던전, 캐릭터·빌런·몬스터, 아이템.
- **맥락을 잊지 않는다.** 앱의 맥락 기억 장치가 고정 기억·관련 기억·연속성·원문을 층으로 넣고, 무엇을 넣었는지 보여 주고, 쓴 뒤 기억과 대조한다.

## 4. 보완 1의 세부 설계 결정

설계서에 없던 구현 세부를 여기서 정한다.

- **위저드 로직은 서버에 둔다.** 문항 선택, id 발급, 병합, 되돌리기, 재검토 판정을 한 곳에서 하고 화면은 보여 주기만 한다. 같은 규칙을 두 번 구현하지 않기 위해서다.
- **인물·세력·체계는 "슬롯"으로 묶는다.** 문항 은행의 `target.slot`(예: `hero`, `support`, `antagonist`)이 같은 문항들은 같은 개체를 채운다. 슬롯의 첫 확정 때 개체 파일을 만들고 id를 발급한다.
- **값 병합은 키 단위다.** 후보의 `값`은 객체이고, 각 키를 `target.path` 아래에 `set` 또는 `append`로 넣는다. `append`된 배열 항목에는 접두어 id(`ru_`, `pl_`, `sec_` 등)를 발급한다.
- **되돌리기를 위해 로그에 이전 값을 남긴다.** `ai/wizard.jsonl`의 각 줄에 `prev`(덮어쓰기 전 값)와 `added_ids`(추가한 항목)를 기록한다.
- **재검토 표시는 계산한다.** 어떤 문항이 확정된 뒤 그 문항이 의존하는 문항이 다시 바뀌었으면 "재검토 필요"다. 별도로 저장하지 않는다.
- **모의 어댑터는 문항 은행의 예시로 답한다.** 문항마다 예시 후보 3개를 둔다. 실제 AI가 없어도 모든 흐름을 시험할 수 있고, 예시는 "직접 쓰기"의 자리표시 문구로도 쓴다.
- **호출 수 상한:** 하루 호출 수와 시간당 호출 수를 앱이 세고, 시간당 20회(기본값)를 넘으면 확인을 받는다. 실제 잔여 한도는 CLI가 알려 줄 때만 표시한다(`rate_limit_info`).
- **실제 호출 전 확인:** "연결 테스트"처럼 구독 한도를 쓰는 버튼은 누르기 전에 그 사실을 알린다.

## 5. 사용자 PC에서 필요한 것 (보완 2)

이 컨테이너에서는 Windows를 실행할 수 없고, 구독 한도를 쓰는 실제 호출은 사용자가 직접 누르는 것이 맞다.

1. Node.js 22 이상 설치 여부 확인(`node --version`).
2. Claude Code 설치·로그인(`claude auth status`), 필요하면 Codex CLI 설치·로그인(`codex login status`).
3. `runebook-personal/app`에서 `node tools/check-env.mjs` 실행 → 생성된 `check-env-result.json`을 전달.
4. 원하면 `node tools/check-env.mjs --live`로 실제 호출 1회(구독 한도를 조금 씀)와 출력 샘플 저장.
5. `룬북.bat` 더블클릭으로 앱 실행 후 위저드 한 단계를 실제 Claude로 진행.
