# 룬북 개인용 · 기본 개념 v0.3 — AI와 함께 쓰고, 함께 그리고, 잊지 않는다

작성 2026-11-01 · 이 문서가 `DESIGN_SPEC.md`(v0.2)보다 우선한다. 충돌하는 절은 4절에 적었다.

## 1. 기본 개념

**룬북은 작가와 AI가 함께 소설을 만드는 프로그램이다.**

| 누가 | 하는 일 |
|---|---|
| 작가 | 방향을 정한다. 장면의 목적과 흐름(비트)을 적고, AI가 쓴 글과 그림을 받아들이거나 고치거나 버린다. 원고의 최종본은 작가가 확정한다 |
| Claude | 글을 쓴다. 세계관·인물을 함께 만들고(위저드), 장면 초안을 쓰고, 이어 쓰고, 다듬고, 설정을 점검한다 |
| ChatGPT | 그림을 그린다. 장면 일러스트, 세계 지도, 도시·던전, 캐릭터·빌런·몬스터 설정화, 아이템 |
| 앱(룬북) | 기억한다. 설정집·줄거리·인물 상태·떡밥·문체를 들고 있다가 AI를 부를 때마다 빠짐없이 넣어 주고, 결과를 기억과 대조해 모순을 찾는다 |

### 1.1 그대로 유지하는 원칙

- 원고와 설정은 작가의 PC에만 저장한다(로컬 우선).
- AI는 작가가 버튼을 눌렀을 때만 부른다. 자동 호출은 없다.
- AI가 쓴 글은 바로 원고가 되지 않는다. "초안"으로 먼저 보여 주고, 작가가 받아들일 때 원고에 들어간다. 받아들인 구간에는 출처(AI 초안)가 기록된다.
- 설정 모순 검사는 그대로 둔다. 오히려 AI가 글을 쓰므로 더 중요해진다.

### 1.2 바뀌는 원칙

| 이전(v0.2) | 지금(v0.3) |
|---|---|
| AI는 질문·점검·선택지만 낸다. 본문 대필 금지 | Claude가 본문을 함께 쓴다. 작가가 결정하고 Claude가 쓴다 |
| 대필 레벨 L0/L1/L2(예시문 80자 등) | 폐기. 대신 공동 집필 모드 4가지(2.1절) |
| 표현 추천은 방법만, 시연 문장은 짧게 | 다듬기 모드에서 실제로 고쳐 쓴 대안을 받는다 |
| 그림 기능 없음(기획서의 화보집은 P2, 생성 안 함) | ChatGPT가 그린다(3절) |
| 맥락은 호출마다 예산 안에서 선별 | 맥락 기억 장치가 중심 기능(4절). 고정 기억은 예산이 부족해도 빼지 않는다 |

### 1.3 알아 둘 점

연재 플랫폼과 공모전마다 생성형 AI 규정이 다르다(기획서 16장: 문피아 공모전은 생성형 AI 활용 금지). 개인용이므로 사용 여부는 작가가 정한다.
대신 앱은 장면마다 AI 기여 기록(AI 초안 여부, 작가가 고친 비율)을 남겨, 나중에 작가가 직접 판단할 수 있게 한다. 이 기록은 밖으로 내보내지 않는다.

## 2. 공동 집필 (Claude)

### 2.1 모드

| 모드 | 작가가 주는 것 | Claude가 주는 것 | 기본 |
|---|---|---|---|
| 비트 → 장면 초안 | 장면 목적과 비트 2~6줄(누가, 무엇을, 어떻게 끝나는지) | 장면 초안 1개(1,500~3,000자) + 기억 갱신안 | 기본 모드 |
| 이어 쓰기 | 커서 위치, 원하는 분량 | 이어지는 본문 + 기억 갱신안 | |
| 다듬기 | 선택 구간과 요청("긴장감 있게", "대사 줄이기") | 고쳐 쓴 대안 2개 | |
| 번갈아 쓰기 | 작가가 쓴 한 단락 | 다음 한 단락 | |

### 2.2 받아들이는 흐름

1. 초안은 에디터 옆 "초안" 영역에 나온다. 원고는 아직 바뀌지 않는다.
2. 작가는 [받아들이기] [일부만 받아들이기(선택 구간)] [다시 쓰기(요청 추가)] [버리기] 중 하나를 고른다.
3. 받아들이면 본문에 들어가고, 그 구간에 출처 표시(AI 초안)가 붙는다. 작가가 그 뒤에 고친 비율은 앱이 계산한다.
4. 같은 때 기억 갱신안(4.4절)이 반영된다.

### 2.3 문체 고정

작가의 문체를 지키기 위해 "문체 가이드"를 고정 기억에 넣는다: 시점, 시제, 문장 길이, 대사 비율, 장르 표현 규칙(설계서 5.3절), 금지어, 그리고 **작가가 직접 쓴 샘플 문단 2~3개**.
작가 샘플은 작품을 시작할 때나 몇 장면을 쓴 뒤 고르게 한다.

### 2.4 출력 형식

본문은 길어서 JSON 안에 넣으면 깨지기 쉽다. 그래서 본문은 그대로 쓰고, 뒤에 구분선과 기억 갱신 JSON을 붙인다.

```
(장면 본문)
===기억===
{"장면요약":"…3줄 이내…","등장":["한도윤","백 노인"],"상태변화":[{"이름":"한도윤","항목":"부상","값":"왼팔 골절"}],
 "새설정후보":[{"종류":"장소","이름":"심층 4층","설명":"…"}],"떡밥":{"심음":["석비의 두 번째 글자"],"회수":[]},"훅유형":"반전"}
```

## 3. 그림 (ChatGPT)

### 3.1 그릴 것

| 종류 | 무엇을 바탕으로 | 어디에 붙나 |
|---|---|---|
| 장면 일러스트 | 장면 요약, 등장 인물 외형, 장소 | 원고의 장면 사이 |
| 세계 지도 | 장소 카드(이름, 방향, 거리, 지형) | 지도 화면 + 장소 핀 |
| 도시·던전 | 장소 카드, 세력, 분위기 | 장소 카드 |
| 캐릭터·빌런 | 인물 카드의 외형·의상·무기·성격 | 인물 카드(대표 이미지) |
| 몬스터 | 몬스터 카드(등급, 서식지, 특징) | 몬스터 카드 |
| 아이템 | 아이템 카드 | 아이템 카드 |

### 3.2 그림도 잊지 않게: 시각 설정집

- **화풍 고정:** 작품 전체의 화풍 문구(예: "수묵 담채풍 판타지 일러스트, 차분한 청록과 먹색")를 모든 그림 프롬프트 앞에 고정한다.
- **외형 고정:** 인물·몬스터·장소마다 "고정 외형 설명"을 둔다. 그림 프롬프트는 이 설명에서 자동으로 조립한다. 외형이 바뀌면(부상, 의상 변경) 시점별 상태(4.3절)를 함께 넣는다.
- **대표 이미지:** 작가가 고른 그림을 그 개체의 대표 이미지로 정하고, 이후 그림을 만들 때 참조 이미지로 함께 넘긴다(참조 이미지를 받는 경로에서만).
- **글자 넣지 않기:** 이미지 생성 모델은 한글을 자주 틀리게 그린다. 지도에는 글자를 넣지 않게 하고, 지명은 앱이 지도 위에 장소 핀으로 얹는다(장소 카드와 연결).

### 3.3 생성 경로

ChatGPT 구독으로 앱이 그림을 자동으로 만들 수 있는 공식 경로가 있는지는 조사 중이다(결과는 이 절에 추가). 경로와 상관없이 다음은 같다.
앱이 프롬프트를 조립하고, 결과 이미지를 `images/`에 저장하고, 개체·장면·지도와 연결한다. 자동 경로가 없으면 "프롬프트 복사 → ChatGPT에서 생성 → 이미지 가져오기"의 반자동 경로가 기본이 된다.

## 4. 맥락 기억 장치

### 4.1 원리

AI는 호출과 호출 사이에 아무것도 기억하지 않는다(무상태 호출, 설계서 8.2절). 그래서 기억은 앱이 들고 있다가 매번 다시 넣어 준다.
"AI가 맥락을 절대 잊지 않게"는 아래 네 가지로 구현한다. AI 모델 자체가 실수할 가능성은 0이 될 수 없으므로 ④의 검사가 마지막 안전망이다.

1. **반드시 넣는 고정 기억:** 작품의 핵심은 예산이 부족해도 빼지 않는다.
2. **자동으로 찾아 넣는 관련 기억:** 이번 장면에 나오는 이름·장소·떡밥을 찾아 그 카드와 "지금 시점의 상태"를 넣는다.
3. **보이는 기억 장부:** 호출마다 무엇을 넣었고 무엇을 요약으로 줄였는지 화면에 보여 주고, 작가가 "이것도 넣기"로 고정할 수 있다.
4. **쓴 뒤 대조:** 초안을 받으면 기억과 대조해 모순(사망 인물 등장, 등급·소속·위치 불일치, 처음 보는 이름)을 표시한다.

### 4.2 기억 층 (프롬프트에 넣는 순서)

잘 바뀌지 않는 것을 앞에 둔다. 같은 앞부분이 반복되면 Claude Code의 프롬프트 캐시가 맞아 구독 한도 소모가 줄어들 수 있다(가설, 실측 필요).

| 층 | 내용 | 예산이 부족할 때 |
|---|---|---|
| M0 고정 | 작품 헌장(장르, 컨셉, 세계 철칙, 힘의 체계, 혼합 정책), 문체 가이드와 작가 샘플, 주인공 카드 전문, 작가가 핀한 카드 | 빼지 않는다 |
| M1 이야기 지도 | 전체 줄거리 계획(아크·회차 계획), 지금까지의 아크 요약 | 빼지 않는다 |
| M2 관련 카드 | 이번 비트와 직전 본문에 나온 이름·별칭으로 찾은 카드 전문 + 그 인물의 현재 상태 | 카드 전문 → 카드 요약으로 줄임 |
| M3 연속성 | 최근 회차 요약, 미회수 떡밥 전부, 최근 사건 | 오래된 회차 요약부터 아크 요약으로 접음 |
| M4 원문 | 직전 장면들의 원문(기본: 최근 2회차) | 가장 먼저 줄인다(최소 직전 장면 1개는 유지) |
| M5 이번 작업 | 장면 비트, 작가 요청 | 빼지 않는다 |

공동 집필 호출은 넉넉한 예산을 쓴다(기본 입력 약 6만 자, 설정에서 조정). 위저드와 추천 호출은 작은 예산을 쓴다.

### 4.3 시점별 상태 추적

인물·세력·장소의 상태는 바뀐다(부상, 사망, 등급 상승, 소속 변경, 위치, 소지품, 비밀을 누가 아는지).
상태 변화는 `memory/state_log.jsonl`에 회차·장면과 함께 기록하고, 호출할 때 "이번 장면 시점의 상태"를 계산해 넣는다. 설정 카드의 처음 값은 바뀌지 않고, 변화만 쌓인다.

### 4.4 기억 갱신

| 때 | 갱신 | 만드는 주체 | 작가 확인 |
|---|---|---|---|
| 장면 초안을 받아들일 때 | 장면 요약, 등장 인물, 상태 변화, 떡밥 심음·회수 | Claude(초안의 `===기억===`) | 자동 반영하고, 기억 화면에서 고칠 수 있다 |
| 새 설정 후보가 나올 때 | 새 장소·인물·규칙 카드 | Claude | 확인해야 반영(설정집에 "후보"로 표시) |
| 회차를 완료할 때 | 회차 요약 | Claude | 자동 반영, 수정 가능 |
| 10회마다 | 아크 요약(오래된 회차 요약을 접음) | Claude | 자동 반영, 수정 가능 |

요약이 원문 대신 기억이 되므로 요약도 검사한다: 원문에서 규칙으로 찾은 핵심 사건(사망, 소속 변경, 등급 변화, 떡밥)이 요약에 들어갔는지, 요약에 나온 이름이 설정집에 있는지.

## 6. 데이터 추가

```
works/<작품ID>/
  memory/
    summaries.json          장면·회차·아크 요약 {"scenes":{sc_id:…},"episodes":{ep:…},"arcs":[…]}
    state_log.jsonl         시점별 상태 변화 {ep, scene, entity, field, value, source}
    pins.json               작가가 고정한 기억(카드 id, 문장)
    ledger/<호출id>.json    호출마다 넣은 기억 목록(층, 항목, 글자 수, 줄인 것)
  chapters/plan.json        아크·회차 계획(회차별 목적과 비트)
  images/
    index.json              items: {id, kind, title, file, prompt, refs:[개체id], provider, parent, pins:[{place, x, y}], created_at}
    im_0001.png
```

`work.json`의 `style`에 `rules`(문체 규칙 목록), `samples`(작가 샘플 문단), `art_style`(화풍 고정 문구)을 추가한다.
인물·장소·몬스터 카드에 `visual`(고정 외형 설명), `portrait`(대표 이미지 id)을 추가한다. 몬스터는 새 엔티티 `monster`(`bible/monsters/mo_0001.json`)로 둔다.
